# Academic Dashboard · Academic Growth System v2

独立的学科成长系统，参考《学霸的黑科技系统》的任务、经验值和晋级体验，但不复制小说设定。**当前 Level 的经验值满格后才可主动申请下一等级考核；考核通过才升级。**

## 本地运行

从 [公开仓库](https://github.com/Away928/knowledge-system-public-core) 下载或克隆代码后，切换到该项目目录。本项目与原作者的本地私有知识库无依赖关系。

```bash
cd knowledge-system-public-core/academic-dashboard
python3 app.py serve --port 8787
# 用户自行访问 http://127.0.0.1:8787
python3 -m unittest discover -s tests -v
```

仅依赖 Python 3 标准库和静态 HTML/JS。只监听 127.0.0.1，不自动打开浏览器或干扰前台。私有状态保存于 Git 忽略的 `data/state.json`，兼容 v1 的 profiles/assessments。注意单独备份真实评分与证据文件。

## 学科范围

学科面板目前包含 **8 个一级学科**：数学、统计学、计算机科学、人工智能、经济学、金融学、物理学、**生物学（Biology）**。生物学独立管理 Lv.1–Lv.7、任务、XP、初始定级及晋级考核；未评估时不推断任何掌握水平。学科细分树仍应从 Learning Hub 获取，Dashboard 不复制其知识点层级。

## 四模块的职责

- **Learning Hub**：Learning Unit、学习状态、学科→分支→知识模块→知识点的知识组织。
- **Cognitive Engine**：知识传授、认知提升、可跳过的日常 Quiz、Session Capture、Cognitive Trace 与知识提炼；这些行为不自动产生 XP/等级。
- **Obsidian Vault**：长期知识内容、来源与原有审批入库。
- **Academic Dashboard**：独立任务发布、成果审核、经验记账、正式学科能力考核与 Level 管理。

系统之间不设强制学习→考核流水线。Dashboard 可按需参考三个旧项目的**只读候选证据**，不修改其数据，不强制组织用户日常学习。

## XP 与升级规则（v2）

1. **首次定级**：未评级的学科可直接申请 Lv.1–Lv.7 的初始能力考核，无需 XP。若无证明仍显示「未评估」，不默认为 Lv.1。
2. **XP 来源**：按需领取并完成系统任务，或自行提交已有学习/实践/科研成果。任务分为知识巩固 10 XP、应用实践 30 XP、研究探索 60 XP，均是尚待校准的**试行奖励**。
3. **可验证交付**：发布任务时指定具体交付与验收标准。提交候选成果本身不会加 XP；审核确认来源、独立完成与未重复计奖后，才记录奖励。同学科同来源引用只奖励一次。
4. **学科经验条**：每个学科有自己的 Lv.1–Lv.7 和当前级经验周期。Lv.1–Lv.6 的升级 XP 阈值必须显式配置，记录依据。**暂不内置任意固定数值**；未配置时 XP 仍能积累，但不能解锁晋级。
5. **满格封顶**：经验值达到阈值后封顶；继续完成任务可以保留成果记录，但该阶段新增 XP 可能为 0。满格仅解锁**自主发起**的下一等级考核。
6. **正式晋级**：无法跳级，也不能在 XP 未满时参加普通晋级考核。失败时保留当前等级与满格 XP，后续可重考；通过时 Level +1，下一阶段经验重新从 0 开始，旧奖励历史仍存。Lv.7 没有更高一级。
7. **单一 Level**：等级同时描述大致教育阶段与可证明能力，不增加 Mastery 第二等级，不将真实学历与游戏评级混同。
8. **手动阈值校准**：对某级的 XP 门槛调整可影响是否已经满格，但**不会自动改变 Level**。该机制应在真实任务量与难度验证后再确定默认门槛。

## 数据及工程边界

- 本地 `data/state.json` 存储 profiles、assessments、quests、achievements、awards、xp_requirements 和 policy_history；使用 stage_id 隔离晋级前后的 XP 周期。
- 初始定级与晋级考核当前采用**人工核验证据 + 人工明确审核**，并非自动命题或阅卷。人工勾选核查框不等于技术上验证了证据真伪。
- 暂未实现自动读取另三个子项目、AI 推荐任务、学科题库/自动评分，以及 Learning Hub 的四层知识树同步；不可宣称这些能力已上线。
- 目前没有多用户权限与身份体系。本地服务不应公开到互联网，审核者需要真实核查证据与独立表现。

## 技术验证

运行 `python3 -m unittest discover -s tests -v`，至少覆盖旧版定级兼容、首次定级、任务/成果审核、同源防重复、满格封顶、失败保留 XP、晋级重置阶段、HTTP 接口和跨源写入阻断。
