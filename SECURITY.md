# Security Policy

## Supported versions

Security reports are considered for the latest public `main` branch and the most recent v0.1 pre-release. Earlier experimental or local copies may not receive separate fixes.

## Report a vulnerability privately

Please **do not** disclose exploitable vulnerabilities, access tokens, credentials, private files or proof-of-concept exploit details in a public Issue.

Use GitHub's **“Report a vulnerability”** / private vulnerability reporting feature on this repository if it is enabled. If that option is not available, open a public Issue **without technical exploit details** asking the maintainer for a private reporting channel. Do not attach secrets to the Issue.

Include a concise impact description, affected component/version, and safe reproduction steps only in a private channel. There is no guaranteed response or remediation service-level agreement.

## Safe-use boundaries

This project is provided **as is**, for local evaluation and development. Do not commit real credentials, private documents or personal data. Read the README's limits before enabling any external API or network-facing service.
