# Contributing

Thanks for helping improve this early public-core project.

## Before submitting a change

1. Check the [README](README.md) and [Release Scope](RELEASE_SCOPE.md) where available so the proposal fits the documented feature boundary.
2. Open an Issue for significant new functionality or changes to existing behavior. Keep proposals small, specific and explain the user-visible benefit.
3. Use a feature branch and a focused pull request. Include a summary, the reason for the change, and steps to reproduce or verify it.
4. Run the repository's documented tests or verifier. If anything cannot be tested, state that in the PR.
5. Avoid new dependencies, heavyweight management layers or duplicate source copies when native tooling or an existing component will do.

## Content and privacy

Only contribute material you own or have a right to redistribute under the project's license. Attribute third-party sources and respect their separate licenses. **Never commit passwords, API keys, private reports, user learning records, financial client material or copyrighted course handouts.**

A green CI run confirms the defined checks passed; it is not a guarantee of correct research results or secure deployment. For sensitive security issues, follow [Security](SECURITY.md), not a public Issue.
